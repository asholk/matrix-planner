# Служебные JSON в `_system/`

Формат файлов, через которые плагин Matrix planner и компаньон для iPhone и iPad обмениваются данными (ТЗ §3.1, §4.4, §4.5, §5.4). Документ — проектный контракт для будущего Swift-компаньона. Это не описание формата какого-либо уже существующего приложения.

Файлы лежат в `<корень Планировщика>/_system/` (по умолчанию `Планировщик/_system/`). Папка видимая, потому что Obsidian Sync не синхронизирует папки с точкой. Чтобы Obsidian Sync передавал эти файлы, в нём нужно включить синхронизацию «Других типов файлов».

Примеры файлов: `fixtures/calendar-cache.json`, `fixtures/tombstones.json`, `fixtures/companion.json`.

| Файл | Пишет | Читает | Код в плагине |
| --- | --- | --- | --- |
| `calendar-cache.json` | Компаньон основного устройства | Плагин, все компаньоны | `src/calendar/cache-schema.ts`, `src/calendar/cache-reader.ts` |
| `tombstones.json` | Плагин (добавляет метки), компаньон основного устройства (может удалять обработанные) | Компаньон основного устройства, плагин | `src/storage/system-records.ts` |
| `companion.json` | Компаньон (всё, кроме `wallpapers`), плагин (только `wallpapers.<профиль>`) | Плагин, компаньоны | `src/storage/system-records.ts` |

## Общие правила

- Кодировка UTF-8, без BOM (BOM при чтении допускается). Плагин пишет JSON с отступом в 2 пробела и переводом строки в конце.
- Ключи — `snake_case`.
- Верхний уровень — объект с целым полем `version`. Версия меняется только при несовместимом изменении. Новые необязательные поля добавляются без смены версии, а читатели игнорируют неизвестные поля.
- Если `version` больше поддерживаемой, читатель не использует данные файла, а писатель ничего в него не пишет.
- Время — ISO 8601 со смещением или `Z`, например `2026-10-10T10:32:05.000Z` или `2026-10-10T13:32:05+03:00`. Плагин пишет в UTC (`Date.toISOString()`).
- Дата — `YYYY-MM-DD`.
- Запись выполняется по схеме «прочитать → изменить только свои ключи → записать». Неизвестные поля и поля другой стороны сохраняются без изменений.
- Повреждённый файл (не JSON, пустой, не объект или с неверным типом списка) плагин не перезаписывает. Он показывает ошибку и ждёт, пока файл исправят или пока компаньон перезапишет его целиком.
- Отсутствие файла не означает удаления данных (ТЗ §5.4.3).

## `calendar-cache.json` — кэш событий «Календаря» iOS

Пишет только компаньон основного устройства. Плагин этот файл **никогда не записывает**: `SystemJsonStore` возвращает для него ошибку `read-only`.

В кэш попадают только календари из настройки «Показываемые календари» и только события из диапазона `range`. Файл синхронизируется на все устройства с хранилищем, поэтому пользователь видит предупреждение о конфиденциальности рядом с настройкой.

### Пример

```json
{
  "version": 1,
  "generated_at": "2026-10-10T06:05:12Z",
  "device_name": "iPhone Александра",
  "time_zone": "Europe/Moscow",
  "range": { "from": "2026-09-10", "to": "2027-04-08" },
  "calendars": [
    { "calendar_id": "8C1F2E3A-0001", "title": "Дом", "color": "#34C759", "kind": "caldav", "allows_modifications": true },
    { "calendar_id": "8C1F2E3A-0003", "title": "Дни рождения", "color": "#8E8E93", "kind": "birthdays", "allows_modifications": false }
  ],
  "events": [
    {
      "id": "E7A1:0002",
      "calendar_id": "8C1F2E3A-0001",
      "title": "Стоматолог",
      "all_day": false,
      "start": "2026-10-10T17:00:00+03:00",
      "end": "2026-10-10T18:00:00+03:00",
      "recurrence": null,
      "item_id": "01JA2B3C4D5E6F7G8H9JKMNPQR",
      "location": "ул. Ленина, 5",
      "url": "matrixplanner://item/01JA2B3C4D5E6F7G8H9JKMNPQR",
      "notes": "Взять полис"
    },
    {
      "id": "E7A1:0003",
      "calendar_id": "8C1F2E3A-0003",
      "title": "День рождения Марии",
      "all_day": true,
      "start": "2026-10-11",
      "end": "2026-10-12",
      "recurrence": "Каждый год"
    }
  ]
}
```

### Верхний уровень

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `version` | целое ≥ 1 | да | Версия формата. Сейчас — `1` |
| `generated_at` | время ISO 8601 | да | Когда компаньон сформировал кэш. По нему плагин определяет устаревание |
| `device_name` | строка или `null` | нет | Устройство, записавшее кэш |
| `time_zone` | IANA-зона или `null` | нет | Зона устройства-писателя. Только для диагностики: плагин переводит время в зону своего устройства |
| `range.from`, `range.to` | дата | да | Границы загруженного диапазона включительно, по умолчанию от −30 до +180 дней от даты записи. `from` не позже `to` |
| `calendars` | массив | нет (по умолчанию `[]`) | Календари |
| `events` | массив | нет (по умолчанию `[]`) | Повторения событий |

### Календарь

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `calendar_id` | непустая строка | да | `EKCalendar.calendarIdentifier` |
| `title` | строка | нет | Название календаря |
| `color` | `#RRGGBB` (допускается `#RGB`) | нет | Цвет календаря. Если цвет не задан или некорректен, используется `#8e8e93` |
| `kind` | `local`, `caldav`, `exchange`, `subscription`, `birthdays`, `other` | нет | Тип календаря по `EKCalendar.type` или источнику. Неизвестное значение читается как `other` |
| `allows_modifications` | логическое | да | `EKCalendar.allowsContentModifications`. Только при `true` календарь можно выбрать для нового события, а его события — изменить. Если значение отсутствует или не равно `true`, календарь только для чтения |

Календарь с повторяющимся `calendar_id` пропускается.

### Событие

Каждое **повторение** повторяющегося события записывается отдельной записью с тем же `id` и своим `start`. Правило повтора не разворачивается на стороне плагина.

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `id` | непустая строка | да | `EKEvent.calendarItemIdentifier`, общий для всей серии |
| `calendar_id` | непустая строка | да | Календарь события |
| `title` | строка | нет | Название |
| `all_day` | логическое | нет (по умолчанию `false`) | Событие на весь день |
| `start` | см. ниже | да | Начало повторения |
| `end` | см. ниже | нет | Конец повторения |
| `recurrence` | строка или `null` | нет | Повтор как текст для показа («Каждую неделю»). Плагин его не разбирает |
| `item_id` | ULID или `null` | нет | `id` заметки-события Планировщика. Если поля нет, `id` извлекается из `url` вида `matrixplanner://item/<id>` |
| `location`, `url`, `notes` | строка или `null` | нет | Место, URL и заметки события |

Формат `start` и `end`:

- **Весь день** (`all_day: true`) — даты `YYYY-MM-DD`; `end` **исключительный**, то есть однодневное событие 11 октября записывается как `"start": "2026-10-11", "end": "2026-10-12"`. Если `end` нет или он не позже `start`, событие считается однодневным. Если вместо даты передана дата-время, используется только дата.
- **Со временем** — время ISO 8601 со смещением (`2026-10-12T10:00:00+03:00` или `…Z`). Плагин переводит его в часовой пояс своего устройства. Время без смещения (`2026-10-12T10:00`) считается плавающим — событие показывается в эти часы в любой зоне. Если `end` нет или он раньше `start`, длительность считается нулевой.

Ключ повторения в плагине — `id` + начало: `<id>@<дата>` для событий на весь день и `<id>@<UTC ISO начала>` для событий со временем. Повторная запись с тем же ключом пропускается.

Событие, у которого есть `item_id` (или ссылка в `url`), связано с заметкой-событием и второй раз в календаре плагина не показывается (ТЗ §4.4).

### Как плагин читает кэш

| Ситуация | Состояние (`CalendarCacheState`) | Что видит пользователь |
| --- | --- | --- |
| Файла нет | `missing` | «Подключите компаньон, чтобы видеть события „Календаря“ iOS» |
| Не JSON, пустой файл, не объект; нет или неверные `version`, `generated_at`, `range`; `calendars` или `events` не массив | `corrupt` | Сообщение о повреждённом файле. События кэша не показываются |
| `version` больше поддерживаемой | `unsupported-version` | «…записаны более новой версией компаньона. Обновите плагин». Данные не читаются |
| Файл в порядке | `ok` | События кэша |
| `generated_at` старше 48 часов | `ok` + `stale: true` | События показываются; интерфейс может показать дату последнего обновления |

Отдельный повреждённый календарь или событие (нет обязательного поля, неверная дата) пропускается, остальные записи читаются.

Покрытие дня (`CacheCoverage`):

- `covered` — дата внутри `range` (включительно);
- `out-of-range` — кэш есть, но дата вне `range`: «События „Календаря“ iOS за этот период не загружены», а не пустой день;
- `no-cache` — кэш отсутствует, повреждён или новой версии.

Событие вне `range` или отсутствие события в кэше **не считается удалением** (ТЗ §5.4.3).

## `tombstones.json` — метки удаления

Плагин добавляет метку, когда пользователь удаляет заметку-событие: сначала метка, затем заметка уходит в корзину. Только по метке основное устройство удаляет событие из «Календаря» iOS.

```json
{
  "version": 1,
  "tombstones": [
    { "id": "01JA2B3C4D5E6F7G8H9JKMNPQT", "kind": "event", "deleted_at": "2026-10-09T18:42:03.120Z", "device_name": "MacBook Air" }
  ]
}
```

| Поле | Тип | Обязательно | Описание |
| --- | --- | --- | --- |
| `version` | целое | да | Сейчас — `1` |
| `tombstones` | массив | да | Метки |
| `tombstones[].id` | строка (ULID) | да | `id` удалённой заметки |
| `tombstones[].kind` | `event` | да | Тип удалённого элемента. Записи других типов плагин пропускает при чтении и сохраняет при записи |
| `tombstones[].deleted_at` | время ISO 8601 | да | Время удаления |
| `tombstones[].device_name` | строка | нет | Устройство, на котором удалили заметку |

Правила:

- **Идемпотентность.** Если метка с таким `id` уже есть (от этого или другого устройства), плагин файл не меняет. Повторное удаление не создаёт дубль.
- **Объединение.** Плагин перечитывает файл непосредственно перед записью и только дописывает свою метку. Чужие метки и неизвестные поля сохраняются.
- Если файла нет, плагин создаёт его с `version: 1`.
- Если файл повреждён или `tombstones` не массив, плагин метку не пишет и возвращает ошибку `tombstone-failed`. Заметка тогда не удаляется.
- Если `version` новее поддерживаемой, плагин не пишет в файл (ошибка `tombstone-failed`).
- Плагин метки не удаляет. Компаньон основного устройства может удалить обработанные метки. Рекомендуется хранить их не меньше 90 дней, чтобы устройство, долго бывшее без связи, не восстановило событие.
- При чтении дубликаты `id` объединяются, остаётся самая ранняя метка.

## `companion.json` — состояние компаньона и статус обоев

Файл общий: основное устройство, время обновления и прочие поля пишет компаньон, а плагин меняет **только** записи `wallpapers.<профиль>`. Все остальные поля, включая неизвестные плагину, сохраняются как есть.

```json
{
  "version": 1,
  "primary_device": "iPhone Александра",
  "last_update": "2026-10-10T06:05:12Z",
  "wallpapers": {
    "iphone-1179x2556": {
      "saved_at": "2026-10-10T10:32:05.000Z",
      "launched_at": "2026-10-10T10:32:06.000Z",
      "confirmed_at": "2026-10-10T10:32:09.000Z",
      "failed_at": null,
      "device_name": "iPhone Александра"
    }
  }
}
```

| Поле | Тип | Пишет | Описание |
| --- | --- | --- | --- |
| `version` | целое | компаньон (плагин — только при создании файла) | Сейчас — `1` |
| `primary_device` | строка или `null` | компаньон | Основное устройство, которое синхронизирует «Календарь» iOS и напоминания |
| `last_update` | время ISO 8601 или `null` | компаньон | Последнее обновление данных компаньоном |
| `wallpapers` | объект | плагин, компаньон | Статус обоев по профилю устройства. Ключ — имя папки профиля в `Обои/`, например `iphone-1179x2556` |
| прочие поля | любые | компаньон | Плагин их не читает и сохраняет |

Статус обоев профиля. Это четыре разных события, и они не смешиваются:

| Поле | Когда записывается |
| --- | --- |
| `saved_at` | Плагин сохранил PNG обоев профиля |
| `launched_at` | Запустилась быстрая команда (по нажатию в плагине или намерением компаньона **Отметить обновление обоев**). Используется для защиты от повторного запуска в течение 10 секунд |
| `confirmed_at` | Установка обоев подтверждена: `x-success` (`obsidian://planner?do=wallpaper-done`) или намерение компаньона |
| `failed_at` | Получен `x-error` (`obsidian://planner?do=wallpaper-failed`) или команда не найдена |
| `device_name` | Устройство, которое последним обновило статус |

Правила записи:

- Плагин меняет только переданные поля профиля. Остальные поля записи профиля, другие профили и поля верхнего уровня сохраняются. Значение `null` очищает поле.
- Если файла нет, плагин создаёт его с `version: 1` и `wallpapers`.
- Если файл повреждён или `wallpapers` не объект, плагин ничего не записывает (ошибка `invalid`).
- Если `version` новее поддерживаемой, плагин ничего не записывает (ошибка `read-only`).
- Компаньон должен так же перечитывать файл перед записью и сохранять `wallpapers`, записанные плагином.

Чтение (`CompanionState`): `missing` — файла нет, `corrupt` — не JSON или не объект, `ok` — `primaryDevice`, `lastUpdate` и `wallpapers`. Некорректные значения времени читаются как `null`.

## Одновременная запись

Внутри плагина записи в один файл выполняются последовательно (очередь по пути). Между устройствами Obsidian Sync передаёт JSON целиком: при одновременной записи с двух устройств может сохраниться только одна версия. Поэтому:

- каждая сторона перед записью перечитывает файл и меняет только свои ключи;
- метки удаления и статусы обоев идемпотентны: повторная запись того же значения безопасна.
